# LogScope 本地日志可视化工具 — 开发计划 V1.0

> 文档版本：V1.0  
> 编制日期：2026-11-20  
> 项目定位：本地、离线、只读的静态日志文件可视化分析器  
> 首要目标：让 Java/Spring Boot 开发者方便地检索 Logback 日志，并通过时间轴快速定位异常。

## 1. 项目目标与范围

### 1.1 核心目标

1. 用户双击应用，选择或拖入 `.log` / `.txt` 文件即可分析，无需启动独立后台服务、配置数据库或安装 JRE。
2. 自动识别常见 Logback 格式；正确处理多行异常堆栈。
3. 以时间轴可视化日志分布，支持框选缩放、平移和错误峰值定位。
4. 支持时间、级别、文件、关键词和正则过滤；展示结果的完整原文及前后上下文。
5. 支持多文件合并时间排序，同时保留每个文件的物理顺序。
6. 以 Rust 实现文件扫描、解析、索引和检索，优先控制内存占用及大文件交互延迟。

### 1.2 V1.0 明确不做

- 持续写入日志的实时追踪、文件监听、增量索引、轮转检测。
- SSH/SFTP、Docker/Kubernetes、远程服务器接入。
- HTTP 服务、Spring Boot 后端、用户登录、云端上传或协同。
- Elasticsearch、外部数据库或必须存在的 SQLite 存储。
- AI 分析、异常自动聚类、完整链路追踪。
- `.gz`、`.zip` 压缩日志解析（预留扩展位，放在 V1.1）。

**约束**：分析过程中按静态文件对待；如检测到原始文件被外部修改或删除，应提示重新导入，不尝试持续追踪。日志仅以只读方式访问，绝不修改原文件。

## 2. 目标用户与使用流程

主要用户：Java / Spring Boot 开发者、测试与运维工程师。

典型流程：

1. 打开 LogScope 桌面应用。
2. 通过文件选择器、拖拽一次导入一个或多个日志文件。
3. 应用展示文件扫描与解析进度，以及解析成功率和时间范围。
4. 查看按分钟或自动粒度汇总的日志量时间轴，ERROR/WARN 分色显示。
5. 框选异常密集时间段，添加关键词/级别/文件筛选。
6. 点击目标日志，在详情面板查看完整堆栈和同文件前后 N 条事件。
7. 需要时复制日志原文或导出当前过滤结果（导出属于扩展优先项）。

## 3. 推荐技术栈

| 层级 | 选型 | 说明 |
| --- | --- | --- |
| 桌面容器 | Tauri 2 | 单机应用，无独立 HTTP API 服务；使用系统 WebView |
| 日志核心 | Rust（稳定版） | 文件扫描、解析、索引和检索 |
| 前端 | Vue 3 + TypeScript + Vite | 页面与交互 |
| UI 组件 | Naive UI 或 Element Plus（二选一） | 表单、目录树、抽屉、主题 |
| 时间轴 | Apache ECharts | 时间密度、框选缩放、平移 |
| 列表 | 虚拟滚动 | 只渲染可见记录 |
| 文件读取 | `std::io::BufReader`、`memchr`、可选 `memmap2` | 默认安全流式读；稳定文件可以评估 mmap |
| 文本查询 | `memchr::memmem`、`regex` | 字节子串及正则 |
| 并行处理 | Rayon（按需） | 多文件扫描与统计 |
| 前后端通信 | Tauri commands + Channel | 命令调用、导入进度与取消 |
| 索引 | Rust `Vec` 等内存数据结构 | V1.0 不依赖持久数据库 |
| 安装分发 | Tauri bundler | Windows 优先，随后 macOS、Linux |

### 3.1 关键架构原则

- **Rust Core 独立于 Tauri**：核心实现为 `logscope-core` crate；UI 只通过稳定命令接口调用。
- **原文不整体复制到内存**：仅保存事件字段、字节偏移和必要索引，详情时按需读取。
- **以事件为单位而非以行作为单位**：单条异常及续行视为同一个日志事件。
- **查询可取消**：大文件正则扫描不得阻塞界面；结果按分页/批量返回。
- **时间精确且可追溯**：时间戳、时区来源、无法解析的时间必须有明确状态。
- **文件只读**：先校验文件身份、大小或修改时间，避免读取已失效的偏移。

### 4.1 文件加载模块

- 支持通过系统文件对话框及拖拽导入本地文件。
- 多文件可并行扫描，但需限制并发，防止磁盘竞争和内存峰值过高。
- 导入展示：文件名、大小、编码、解析器、事件数、时间范围、WARN/ERROR 数、耗时、状态。
- 自动探测 UTF-8 / UTF-8 BOM；其他编码通过采样检测和手动选择兜底。
- 读取器按照**字节**计算 `start_offset` / `end_offset`，不得以字符数计算。
- 为用户提供取消导入的能力；取消时清理未完成索引并关闭文件句柄。

### 4.2 日志解析模块

**第一批目标格式**：

- 常见 Spring Boot / Logback 文本 Pattern。
- 自定义带日期、线程、级别、Logger、消息的 Pattern。
- 可选 JSON Lines（如果研发工期紧，顺延到 V1.1）。

解析流程：采样 → 自动识别 → 用户预览 → 事件边界检测 → 字段解析 → 多行续行合并 → 索引输出。

特别要求：

- 通过“新日志起始行”识别事件边界；其余行拼入当前事件。
- 异常堆栈中的 `at ...`、`Caused by:`、`Suppressed:` 等均作为续行保留。
- 限制异常超长事件的行数或字节数，防止异常格式引发无限合并。
- 解析失败的内容保留为 `UNKNOWN` 事件，展示失败原因，不静默丢弃。
- 时间戳有时区则使用原始时区；没有时区时使用工作区配置（默认 `Asia/Shanghai`，可修改）。
- 同一毫秒中的事件，通过文件内顺序稳定排序。

### 4.3 内存索引模块

建议基础事件索引字段：

```rust
struct LogEntry {
    timestamp_ms: Option<i64>,
    start_offset: u64,
    end_offset: u64,
    file_id: u32,
    sequence_no: u32,
    level: LogLevel,
    // 其他字段可按需存储或由原文解析获得
}
```

数据结构：

- `Vec<LogEntry>`：按文件内原始顺序存放。
- `Vec<EventRef>`：按时间戳、文件、序号稳定排序的全局视图。
- 按文件、级别及时间范围预过滤。
- 时间缺失的事件保留在“未知时间”分组，不强行插入虚构时间轴。
- `EventRef` 用稳定标识 `{file_id, sequence_no}`，避免过滤后错位。

**不采用的做法**：一次性把所有日志 `String` 装入 `Vec<String>`；让 Vue 接收全部记录；在 UI 线程中执行正则全文扫描。

### 4.4 检索模块

MVP 条件：文件、时间范围、级别、纯文本子串（默认不区分大小写选项）、前后上下文。

V1.0 补充：正则搜索、搜索取消、查询历史（会话内）、组合条件。

搜索流程：

1. 根据已解析时间和文件范围得到候选事件。
2. 执行级别、Logger 等低成本过滤。
3. 对需要文本匹配的候选事件按偏移读取原文，执行子串或正则匹配。
4. 形成稳定排序后的结果索引，以游标/批量方式向 UI 输出。
5. 列表只读取当前可视窗口的摘要，详情面板按需请求完整原文。

技术注意：

- 多文件查询的“时间排序”与上下文的“同文件原始顺序”是两种不同索引。
- Rust `regex` 不支持任意回溯语法，如前后向断言；界面应告知支持的正则语法。
- 复杂文本查询可以采取后台任务 + 进度 + 取消；不能假定所有查询能瞬时完成。
- 任何查询均须处理无时间、错误编码、超长单行以及异常格式。

### 4.5 时间轴模块

- 默认按当前文件总时间跨度自动分桶（秒 / 10 秒 / 分钟 / 小时等）。
- 按总数、INFO、WARN、ERROR 分层统计。
- 用户能框选区间缩放、左右平移、重置视图、点击异常峰值。
- 时间范围改变时与日志列表联动；文本过滤变化时明确显示“全量时间轴”或“当前过滤结果时间轴”。
- 图表目标输出不超过约 1,500 个时间桶，避免无意义地渲染每个事件。
- 首次导入生成基本时间桶；切换精度时利用内存索引重新聚合。

### 4.6 UI 模块

建议布局：

```text
┌──────────────────────────────────────────────────────────────┐
│ 顶部：导入文件  搜索关键词  级别/时间过滤  设置             │
├──────────────┬───────────────────────────────────────────────┤
│ 文件列表     │ 日志密度时间轴（缩放 / 框选 / 平移）         │
│ - app.log    ├───────────────────────────────────────────────┤
│ - error.log  │ 虚拟滚动日志列表                             │
│ - 其他文件   │ 时间 | 级别 | 线程 | Logger | 摘要           │
│              │                                               │
├──────────────┴───────────────────────────────────────────────┤
│ 详情抽屉：完整原文 / 堆栈 / 上下文 / 复制                 │
└──────────────────────────────────────────────────────────────┘
```

- 默认深色主题、支持浅色主题。
- 日志级别颜色一致，不只靠颜色识别。
- 搜索词高亮，长行可横向滚动或按需换行。
- 列表使用虚拟滚动，滚动过程中不实时传输全量数据。
- 支持错误日志上一条/下一条快速跳转。
- 展示导入和搜索进度、错误信息与取消按钮。

## 5. Tauri 命令接口草案

| 命令 | 输入 | 输出 |
| --- | --- | --- |
| `open_files` | 文件路径列表、解析设置 | 任务 ID |
| `get_import_status` | 任务 ID | 进度、统计、错误 |
| `cancel_import` | 任务 ID | 取消结果 |
| `list_files` | 无 | 文件元数据列表 |
| `get_timeline` | 文件 ID、时间范围、级别、桶配置 | 时间桶数组 |
| `search_logs` | 查询条件、数量上限、游标 | 事件摘要、后续游标 |
| `cancel_search` | 查询 ID | 取消结果 |
| `get_log_detail` | 事件引用 | 完整原始事件 |
| `get_log_context` | 事件引用、before、after | 同文件前后事件 |
| `close_files` | 文件 ID 列表 | 释放索引结果 |

**注意**：命令名为草案。耗时操作应通过任务 ID + Channel 发送进度，而不是让 UI 同步等待全部扫描结束。

## 8. 性能与质量验证

性能数据均为**待实测的目标**，不应当在没有测试前作为性能承诺。

| 测试项 | 初步目标/原则 |
| --- | --- |
| 100MB 日志导入 | 在常见开发机 NVMe SSD 上尽量做到 10 秒内完成基础索引 |
| 1GB 日志导入 | 目标 90 秒内完成基础索引，需基准测试修订 |
| 内存占用 | 不与原始文件字节数线性增长；以事件数和附加索引为主 |
| 时间/级别过滤 | 常规筛选应流畅，并测量 P95 延迟 |
| 时间轴点数 | 单次图表返回约 1,500 桶以内 |
| 大量结果显示 | 采用虚拟滚动和分批结果，不渲染全部记录 |
| 正则搜索 | UI 可取消；极端查询有限流或资源限制 |
| 源文件安全 | 原文件只读，文件变更后不会静默显示错误原文 |

测试夹具应覆盖：LF/CRLF、UTF-8 中文、时间戳缺失、乱序、同毫秒、空文件、无结尾换行、数十 MB 超长事件、异常堆栈、非 Logback 文本，以及多文件重复时段。

## 9. 主要风险和应对

| 风险 | 应对方式 |
| --- | --- |
| 不同 Logback Pattern 差异大 | 内置多个解析器 + 采样预览 + 自定义规则 |
| 多行堆栈错误合并 | 日志头状态机 + 失败回退 + 最大事件限制 |
| 字节偏移与中文错位 | 先记录字节边界，再解码；自动化测试 |
| 无时间戳或乱序事件 | 单独未知时间分组，保留物理顺序 |
| 内存索引过大 | 紧凑结构、限制额外字段、按需加载原文 |
| 全文扫描较慢 | 先过滤时间/级别，再读取候选事件；支持取消 |
| mmap 文件被外部修改 | 默认采用缓冲读取；mmap 仅对稳定文件使用并检测失效 |
| Tauri 不同 OS WebView 行为差异 | Windows 优先验收，再逐平台测试 |
| 复杂图表拖慢 UI | 降采样、聚合桶、虚拟列表、操作节流 |

## 10. 开发启动顺序（建议）

第一轮不要先做漂亮 UI，先验证核心能力：

1. 用 Rust CLI 输入一个真实 Logback 文件，输出事件数、ERROR 数、时间范围和解析失败数。
2. 输入事件 ID，可以按原始字节偏移准确读出完整日志（包括多行堆栈）。
3. 实现按时间/级别/关键词过滤和前后文查询。
4. 通过 100MB / 1GB 文件初测，确认内存索引设计合理。
5. 再接入 Tauri + Vue 时间轴、虚拟列表和详情面板。

**第一条完整可验收路径**：

> 双击 LogScope → 选择 `application.log` → 解析并展示时间轴 → 框选 ERROR 高峰 → 搜索异常关键字 → 查看完整堆栈和前后 20 条日志。

当这条链路稳定且性能可接受时，MVP 就具备实际使用价值。

---

**最终决策摘要**：Tauri 2 + Vue 3 + Rust Core；完全离线、纯桌面、静态文件、只读、内存索引优先；不做后台服务、数据库依赖、实时流或远程接入。
